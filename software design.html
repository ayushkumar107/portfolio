Introduction to Software Design

  • Definition: Software design is an iterative process through which requirements are translated into a blueprint for constructing the software.
  • Transition: It serves as the bridge between the analysis phase (what the system should do) and the implementation phase (how the system is built).
  • Blueprint Aspect: It focuses on the internal technical structure, including data structures, software architecture, interface representations, and procedural details.
  • Importance: A well-documented design reduces the risk of errors during coding and simplifies the long-term maintenance of the software.

Basic Concepts of Software Design

  • Abstraction: Dealing with complexity by hiding unnecessary details and emphasizing essential features.
  • Refinement: The process of elaboration where high-level descriptions are broken down into detailed instructions.
  • Modularity: Dividing software into identifiable and manageable components called modules.
  • Architecture: The overall structure of the software and the ways in which that structure provides conceptual integrity.
  • Information Hiding: Designing modules such that internal data and logic are not accessible to other modules that do not need them.

Architectural Design

Architectural design represents the high-level view of the system. It involves identifying the major hardware and software components and their communication paths.

Common Architectural Types:

  • Layered Architecture: Components are organized into layers (e.g., Presentation, Business, and Data layers). Each layer provides services to the one above it.
  • Client-Server: The system is split into service providers (servers) and service consumers (clients).
  • Microservices: A modern approach where the application is built as a suite of small, independent services communicating via APIs.

Low-Level Design (LLD)

While architectural design focuses on the "macro" view, LLD focuses on the "micro" details of the software components.

  • Detailed Components: It provides the internal logic for each module identified in the architectural phase.
  • Algorithms: Developers define the specific step-by-step logic and mathematical formulas required for processing.
  • Data Structures: Selection of appropriate data types (Stacks, Queues, Linked Lists) to handle data efficiently.
  • Purpose: To provide enough detail so that a programmer can write the code directly from the design document.

Modularization

Modularization is the technique of decomposing a software system into smaller, independent modules.

Core Benefits:

  • Easier Maintenance: Changes in one module are less likely to impact the entire system, making it easier to fix bugs.
  • Reusability: Individual modules can be used in other projects or different parts of the same project.
  • Manageability: Large teams can work on different modules simultaneously without interfering with each other's work.
  • Readability: Smaller sections of code are easier for humans to understand and review.

Design Structure Charts

A Structure Chart is a top-down modular design tool that shows the relation between modules of a software system.

  • Hierarchy: It represents the system in a tree-like structure, showing which modules call which sub-modules.
  • Information Flow: It uses "arrows" and "couples" to show what data and control signals are passed between modules.
  • Organization: Unlike flowcharts, structure charts show the *organization* of modules rather than the sequence of execution steps.
  • Analysis: It helps designers identify if a system is too complex or if a module is performing too many tasks.

Pseudocode & Flowcharts

Pseudocode

  • A high-level description of an algorithm using a combination of English and programming logic.
  • It ignores syntax and focuses on the logical flow.
  • Easier for non-programmers to understand the logic.

Flowcharts

  • A graphical representation of the sequence of operations in a program.
  • Uses symbols like diamonds (decisions), rectangles (processes), and ovals (start/end).
  • Excellent for visualizing conditional branches and loops.

Coupling & Cohesion

These are the two primary metrics used to measure the quality of a software design.

  • Coupling: Measures the degree of interdependence between different modules.
    • Goal: **Low Coupling** is desirable so that changes in one module don't break others.
  • Cohesion: Measures the strength of the relationship between elements within a single module.
    • Goal: **High Cohesion** is desirable, meaning a module does one specific task and does it well.
  • The Ideal Design: A system with High Cohesion and Low Coupling is considered robust and easy to maintain.

Design Strategies

Design strategies are systematic approaches to creating a software design. The choice depends on the project size, complexity, and language being used.

  • Function-Oriented Design: Focuses on the functions/processes that transform data.
  • Object-Oriented Design: Focuses on real-world objects and their interactions.
  • Top-Down Strategy: Starts with the highest level of the system and breaks it down.
  • Bottom-Up Strategy: Starts with the smallest components and integrates them into a larger system.

Function-Oriented Design

  • Overview: This approach treats a system as a group of interacting functions. Each function has a specific task.
  • Data Flow: It relies heavily on Data Flow Diagrams (DFDs) to show how data moves from one process to another.
  • Centralized State: Often, data is maintained in a centralized state (like a database) and various functions access and modify it.
  • Usage: Primarily used in procedural programming environments (like C programming).
  • Focus: What does the system *do*? (The processes).
Software Design & MetricsSlide 11

Object-Oriented Design (OOD)

  • Overview: Based on the concept of "Objects" which represent real-world entities. Objects contain both data (attributes) and methods (behavior).
  • Key Concepts:
    • Encapsulation: Bundling data and methods together inside a class.
    • Inheritance: Allowing a new class to inherit features from an existing class.
    • Polymorphism: Allowing different objects to respond to the same command in different ways.
  • Advantage: Much better for large-scale, complex systems because it mimics real-world logic and promotes reuse.
